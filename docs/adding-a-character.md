# Adding a character

Characters are data. A new character that reuses one of the existing body shapes needs **no C++
changes**: only an entry in `firmware/data/assistant.json` (plus, optionally, preview GIFs for the
web UI). A brand-new body shape needs a small drawing function.

## 1. Add the entry to `firmware/data/assistant.json`

Append an object to `characters`:

```json
{
  "id": "na",
  "name": "Na",
  "kind": "quả na xanh",
  "voice": "Zephyr",
  "tagline": "Tò mò, hay hỏi, thích khám phá",
  "persona": "Bạn là Na, một quả na xanh tò mò ... Bạn xưng \"Na\" và gọi người dùng là \"bạn\". Tính cách: ...",
  "look": {
    "shape": "mochi",
    "body": "#A8D88A",
    "accent": "#6FA556",
    "ink": "#2F4022",
    "cheek": "#F5A77B"
  }
}
```

Fields (validated by `firmware/scripts/validate_data.py`, used by `assistant_config.cc`):

| Field | Required | Rules |
| --- | --- | --- |
| `id` | yes | Lowercase `[a-z0-9_]`, at most 13 characters (stored in NVS as `c_<id>`; NVS keys are limited to 15). Unique. Never rename it later: settings and overrides are keyed by it. |
| `name` | yes | Display name with diacritics. The user can say it to switch (`nhan_vat.doi` tool, `SetActiveCharacter()`). |
| `voice` | yes | A Gemini Live prebuilt voice, for example `Leda`, `Aoede`, `Kore`, `Zephyr`, `Puck`, `Charon`, `Fenrir`, `Orus`, `Achird` (the web UI list is `VOICES` in `firmware/web/index.html`). |
| `persona` | yes | Vietnamese system prompt for the character: who it is, how it addresses itself and the user, personality. Keep it to a short paragraph; `common_rules` is appended automatically by `SystemPrompt()`, so don't repeat the shared rules. |
| `look.shape` | yes | One of the shapes drawn by `BuildBody()` in `firmware/src/assistant/assistant_face.cc`: `cloud`, `corn`, `avocado`, `mochi`, `robot`. Unknown values fall back to `cloud`. |
| `look.body`, `accent`, `ink`, `cheek` | recommended | `#RRGGBB`. `body` is the main fill, `accent` details (leaves, pit, visor), `ink` eyes and mouth, `cheek` blush. The screen uses a dark background (`0x15131F`), so check contrast. |
| `kind` | recommended | Short description ("quả na xanh"); used when the prompt lists the other characters. |
| `tagline` | recommended | One line shown when the user scrolls to the character with the wheel. |

To make it the default for new devices, set `"default_character": "na"`.

Validate:

```bash
python3 firmware/scripts/validate_data.py
```

## 2. Preview GIFs for the web UI (optional but recommended)

On the device, faces are drawn natively from `look`, so the character already works after step 1.
The web UI shows GIF previews from the assets partition (`/face?c=<id>&e=<emotion>`), generated by
`firmware/assets/make_faces.py`. Its `CHARACTERS` table maps an id to a body drawer:

```python
CHARACTERS = {
    "bong": (draw_cloud, 0),
    ...
    "na": (draw_mochi, 4),   # (body drawer, face vertical offset)
}
```

The drawers have their own colors; for a recolored character, add a `draw_<name>()` function next to
`draw_mochi()` with the new palette. Then regenerate and rebuild the assets:

```bash
uv run --with pillow python firmware/assets/make_faces.py firmware/assets/faces --only na
firmware/build_assets.sh && firmware/flash_assets.sh
```

## 3. A new body shape (only if none of the existing ones fit)

1. In `firmware/src/assistant/assistant_face.cc`, add a branch to `BuildBody()`:

   ```cpp
   if (look.shape == "custard_apple") {
       Shape(p, 160, 176, 250, 250, body);   // filled shapes in the 320x320 design space
       // ... details with accent, Arc(), etc.
       return {160, 170};                    // where the face (eyes, mouth) is centered
   }
   ```

   Use the existing helpers `Shape()`, `Arc()`, `Hex()`; coordinates are in the 320x320 design
   space (`kDesign`) and scaled with `Px()`. Keep the object count small: it is redrawn on every
   character change.
2. Add the shape name to `KNOWN_SHAPES` in `firmware/scripts/validate_data.py`.
3. Add a matching `draw_<shape>()` to `make_faces.py` for the web previews.
4. Build, flash and check the expressions listed in `kExpressions` (23 of them). Talking to the
   character cycles through most of them; `/screen.jpg` in the web server gives a screenshot.

## 4. Try it

```bash
firmware/build.sh && firmware/flash_app.sh     # or: firmware/ota.sh bap-xxxx.local
```

- Rotate the wheel while resting: the new character appears with its tagline.
- Or say "cho mình gặp Na": the `nhan_vat.doi` tool switches and restarts the session with the
  new voice and persona.
- In the web UI you can tweak the name, voice and persona without rebuilding. Those edits are
  saved per device in NVS (`SaveCharacterOverride()`); copy the final version back into
  `assistant.json` to ship it.

## Persona tips

- Write in natural Vietnamese and fix how the character addresses itself and the user
  ("Bạn xưng \"Na\" và gọi người dùng là \"bạn\"").
- Describe tone and quirks in a few words; avoid long lists of catchphrases (the model overuses
  them). Everything is spoken, so no emoji or formatting.
- Characters for children (like Mochi) should say explicitly that content stays child-friendly.
- Keep the persona under about 1500 bytes: it is sent on every session and the override must fit
  in one NVS string (`SaveCharacterOverride()` drops overrides of 3900 bytes or more).
