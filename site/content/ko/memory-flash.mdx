# 메모리와 플래시

![플래시 구성](/diagrams/flash-layout.svg)

## 플래시 (32 MB)

| 오프셋 | 내용 | 쓰는 주체 |
| --- | --- | --- |
| `0x0` | 부트로더 | `flash.sh` |
| `0x8000` | 파티션 테이블 (`partitions/v2/32m.csv`) | `flash.sh` |
| `0x9000` | `nvsfactory`, 200 KB: Seeed 기기 EUI와 키 | **절대 쓰지 않음** |
| `0x3B000` | `nvs`, 840 KB: 설정, 메모, 기억, 알람 | 펌웨어 |
| `0x10D000` | `otadata` | `flash.sh`, OTA |
| `0x200000` | `ota_0`, 4 MB: 앱 | `flash.sh`, `flash_app.sh`, OTA |
| `0x600000` | `ota_1`, 4 MB: 다른 OTA 슬롯 | OTA |
| `0xA00000` | `assets`, 16 MB: 글꼴, 얼굴, 호출어 모델 | `flash.sh`, `flash_assets.sh` |

<Callout type="warning">
`nvsfactory`에는 Seeed가 기기에 넣은 키가 있습니다. Bắp 스크립트는 이곳을 쓰지 않으므로 언제든 공식
펌웨어로 돌아갈 수 있습니다.
</Callout>

## RAM

ESP32-S3에는 약 512 KB의 내부 SRAM이 있고 Watcher는 8 MB PSRAM을 더합니다. 부족한 것은 내부 RAM입니다.
Wi-Fi, TLS(하드웨어 AES DMA 버퍼), 오디오, LVGL이 모두 이것을 원합니다.

| | 대기 중 | 관측된 최저 |
| --- | --- | --- |
| 내부 RAM 여유 | 55–60 KB | 약 33 KB |
| PSRAM 여유 | 약 3.2 MB | |

Bắp이 이를 지키는 방법:

- cJSON과 작은 할당은 PSRAM으로 갑니다. 256바이트 이하 요청만 내부에 남습니다.
- 플래시를 건드리지 않는 작업의 스택은 PSRAM에서 실행됩니다(`xTaskCreateWithCaps`): Opus 코덱,
  알림 플레이어, Zing 플레이어.
- Wi-Fi와 lwIP 버퍼는 PSRAM에 두고, 그 자리를 16 KB TCP 윈도우에 써서 Gemini 오디오가 매끄럽게
  들어옵니다.
- LVGL 작업 스택은 12 KB이며(예전에 넘친 적이 있음), `/api/perf`가 작업별 최소 스택 여유를 보고해
  문제를 일찍 발견합니다.
- 웹 서버는 열린 소켓 4개, lwIP는 전체 16개로 제한합니다.
