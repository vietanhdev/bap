# 성능

아래 숫자는 모두 실제 Watcher에서 최적화 전후로 측정한 값입니다.

![전후 비교](/diagrams/performance.svg)

| 지표 | 이전 | 이후 |
| --- | --- | --- |
| 호출어에서 듣기까지 | 2.9초 | 1.4–2.3초 |
| Gemini TLS 핸드셰이크 | 1.36초 | 약 0.1초 (재개) |
| Zing MP3 검색 | 2.5초 | 1.0초 |
| 날씨 답변 | 6초 | 약 2.7초 |
| 듣는 얼굴 애니메이션 중 CPU | 19.5% | 6% |
| 음악 재생 중 CPU | 14.7% | 1.3% |
| 펌웨어 크기 | 3.83 MB | 3.31 MB (4 MB 슬롯의 79%) |
| OTA 업로드 | 112초 | 약 30초 |

## 차이를 만든 것

- **TLS 세션 티켓.** `TicketSsl`이 호스트별로 세션을 저장했다가 다음 연결에 제시합니다. Gemini, 날씨,
  Zing, 라디오 등 모든 외부 요청이 이를 거칩니다.
- **더 빠른 ECC.** `MBEDTLS_ECP_FIXED_POINT_OPTIM`이 전체 핸드셰이크마다 약 330 ms를 아끼고 RAM은
  약 4 KB 더 씁니다.
- **안전한 곳엔 일반 HTTP.** 공개 날씨·지오코딩 데이터는 HTTP로 받아 핸드셰이크를 피하고, 키나
  개인 데이터가 있는 요청은 HTTPS를 유지합니다.
- **다시 그리기 줄이기.** 투명도를 약 11단계로 양자화하고, 듣기 파형은 3단계로 맥동하며, 밤 얼굴은
  정지 화면입니다. LVGL은 25 fps로 동작합니다.
- **더 작은 이미지.** 쓰지 않는 오디오 코덱(FLAC, Vorbis, AMR, ADPCM, ALAC, SBC, LC3, G.711/722)을
  빌드에서 뺐습니다.
- **OTA.** 쓰기 전에 플래시 영역을 미리 지우고, 업로드 중에는 호출어·카메라 추론·터치 폴링을 멈춥니다.
- **세션 재개.** 프롬프트와 목소리가 그대로일 때만 재개 핸들을 다시 써서, 이어지는 질문은 설정
  과정을 건너뜁니다.

## 직접 확인하기

```bash
curl -s http://bap-xxxx.local/api/perf | python3 -m json.tool
```

응답에는 작업별 CPU와 최소 스택 여유, 현재·최소 내부 RAM, PSRAM 여유, 가동 시간, Wi-Fi 신호가
있습니다. 시스템 탭의 *기기 상태*도 같은 데이터를 보여 줍니다.
